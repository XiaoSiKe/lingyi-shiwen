# 核心设计

**零一拾文 · 公众号自适应采集引擎**，初步雏形开发者：**Spark**。

## 一份源码，两个调用层

```text
用户自然语言
  → SKILL.md 选择模式与解释边界
  → scripts/shiwen.py
  → wxrc.cli
  → 列表 / 正文 / 搜索 / 后台通道
  → RiskEngine 请求与限速
  → 解析 → 文件与索引
```

Skill 不复制采集逻辑。Python 模块名保留 `wxrc`，兼容原始源码导入；项目展示名、Skill 名和新入口已统一。浏览器功能统一由本项目的 Playwright 适配层实现。

## 关键责任

| 模块 | 负责什么 |
|---|---|
| `session.py` | 实际请求、账号身份、逐请求配额与限速、重试中的熔断检查 |
| `account_pool.py` | 无计费选择、实际请求计费、账号可用性、冷却与续期 |
| `guard.py` | HTTP 状态、验证页结构和 JSON 返回码的统一判定 |
| `getmsg.py` | 翻页、日期边界与持久待处理队列 |
| `crawl.py` | 成功归档去重、失败元信息补采、正文与索引落盘 |
| `article.py` | 保留文本顺序的 DOM 解析与 Markdown 输出 |
| `storage.py` | 稳定资源标识、文件原子替换和敏感文件权限 |
| `security.py` | 日志敏感参数与代理凭证脱敏 |
| `browser.py` | 可选浏览器、人工验证与出口继承 |

## 恢复语义

列表取得一页后，将所有符合条件的待处理文章与下一页 offset 一起原子写入游标。每次 `yield` 后，只有下游恢复迭代，才确认该文章已处理并从队列移除。

因此中断可能导致一次安全重放，不应造成待处理文章丢失。`ArchiveJob` 使用成功索引消除重复；失败记录独立保留为 `meta_only`，下次运行先补采。页内 `limit` 只暂停消费，保留本页余项。旧版游标缺少队列，会重新枚举，用已有成功索引去重。

文件写入先于索引写入。正文、正文 HTML、游标与登录态通过同目录临时文件、flush/fsync、原子替换保存。CLI 使用操作系统文件锁保护单一输出目录，进程退出自动释放。直接 Python API 调用方仍需自行协调并发；该版本没有多文件数据库事务。

## 请求语义

通道通过 `account=...` 传入实际账号，由引擎统一处理头部、身份绑定、每次实际尝试的计费、rpm 预约和风险反馈。外层列表通道可以在合法可用账号间重放，但显式账号请求不会在引擎内换号后继续发送旧凭证。

HTTP 5xx 属于服务错误，正文节点中的文字不会因“环境异常”等词触发验证页判定。熔断在每次重试发送前检查；账号或配置的出口不可用时暂停。浏览器兜底不得改变配置出口。

## 验证范围

`tests/test_first_round.py` 覆盖第一轮修复及 Skill 脚本从其他工作目录执行的能力。原有测试继续覆盖本地模拟列表、正文、搜索与后台解析。浏览器适配层使用离线模拟验证；真实页面 fixture 缺失时保留条件跳过。

未验证条件包括真实微信账号长期运行、各版本后台字段差异，以及真实浏览器与微信线上环境的组合。JSONL 索引目前仍是追加记录，尚未引入 SQLite、定时增量采集或跨进程任务管理。

## v0.2.0 链接任务

TextRun 复用成功索引并核验正文与所需 HTML 是否存在；最近任务的 pending、结果和计数通过原子运行报告保存。强制刷新会追加一次成功记录。管理员正文也复用 TextRun 的获取、校验与保存逻辑；后台清单仍为独立快照。

## v0.3.0 范围报告与增量检查

`reporting.Coverage` 统一维护范围、页数、停止原因与错误类型。各列表通道在实际退出分支设置原因，归档层将扫描完成与正文成功分别记录。增量模式从最新页枚举并复用归档索引，使用内存游标；历史恢复继续使用持久游标。预览清单同样使用内存游标，不消耗历史恢复进度。
